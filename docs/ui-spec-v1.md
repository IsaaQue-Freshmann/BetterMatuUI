## 1. 界面层级：两层

```
主界面                          设置界面
├── 左侧菜单栏                  ├── 独立窗口（macOS 惯例：⌘,）
└── 右侧详细界面（随菜单切换）    └── 入口：个人中心页 / 快捷键
```

## 2. 左侧菜单栏

竖向排列，自上而下：

| 位置 | 内容 |
| --- | --- |
| 顶部 | logo：**BetterMatuUI** |
| 1 | 我的班级 |
| 2 | 题目中心 |
| 3 | 数据中心 |
| 4 | 系统帮助 |
| 底部（固定吸附） | 个人中心 |

要点：

- 四个菜单在上、个人中心**始终贴在最底部**（✱ 与上面之间加一条分隔线）。
- **折叠态**：一键（一个图标）在"展开态 ↔ 折叠态"间切换。折叠后只显示 5 个位图图标，侧栏宽度收窄。
  ✱ 我的推断：宽度约 220px → 64px；折叠后 logo 缩成方形标记；图标 hover 时弹文字提示；折叠状态记住（下次启动保持）。
- 与原站菜单的差异：原站是"课程中心 / 题目中心 / 个人管理 / 系统帮助"，
  我们改为"我的班级 / 题目中心 / 数据中心 / 系统帮助 / 个人中心"，去掉课程申请等写操作入口。

## 3. 右侧详细界面 ·「我的班级」（本轮开发）

分**左右两区**。

### 3.1 左区 · 目录浏览器

```
┌─────────────────────────────────────────────┐
│  ← →        当前位置：我的班级 / 作业列表 /   │  ← 功能栏
│                    c语言 / 第1次上机          │
├─────────────────────────────────────────────┤
│  ▸ 作业列表              c语言      2026-09-17│  ← 竖向树状列表
│    ▾ 第1次上机            9 题      权重 0.1  │
│        1_输出n的1-5次方    C++      10 分     │
│        计算e的x次方        C++      15 分     │
└─────────────────────────────────────────────┘
```

- 顶部功能栏：**前进 / 后退**按钮 + **当前位置详情**（路径 + 该层级的统计信息）。
- 主体：竖向树状列表，macOS 访达风格，**列表形式**（不是图标网格）。
- **可展开、也可进入**：能就地展开子节点，也能双击"进入"下一层。
  ✱ 我的推断：单击 = 选中并展开/收起；双击 = 进入并推入历史；前进/后退沿历史移动。
- 每行右侧标注详细信息，跟网站走：时间、语言要求、编译类型、分值、允许提交次数等。
- 层级示例（你给的）：`我的班级 / 作业列表 / c语言 / 第一次上机 / 计算e^x`
  ✱ 对应站点真实数据：班级（课程 `c语言`，班级 `2026软件设计思想与方法1`，分数 7.0）
  → 作业列表（`操作环境练习` 权重 0.0、`第1次上机` 权重 0.1）→ 作业内题目。

### 3.2 右区 · 代码区（上下分栏）

```
┌──────────────────────────────────────────────────┐
│  题面 / 编辑器（语法高亮）              [ 提交 ]  │  ← 上栏
│                                                   │
├──────────────────────────────────────────────────┤
│  提交结果                                          │  ← 下栏
│  得分：0      扣分：100                            │
│  扣分原因：When test group(1) step(1),the input    │
│           is (),the real output is not right.      │
└──────────────────────────────────────────────────┘
```

- 上栏：文本编辑器 + **语法高亮**；右上角**提交**按钮。
- 提交按钮 → 弹"是否确认提交"确认框，带**"记住我的选择"**。
  ✱ 理解为"不再询问"：勾选后以后点提交直接提交，可在设置里重置。
- 下栏：**提交结果**——提交一次、拉取一次，**不做定时轮询**。
  内容：得分、扣分项、扣分原因。
  ✱ 数据来自 `scoredetail` 页：`扣分:N` + 评测失败原因（第几个测试组、第几步、输入是什么、为什么错）。

### 3.3 选中不同层级时右区显示什么（✱ 未说明，这是我的方案）

| 左区选中的节点 | 右区显示 |
| --- | --- |
| 题目（叶子） | 题面 + 编辑器 + 提交结果 |
| 作业（文件夹） | 该次作业的题目总览（题目 / 语言 / 允许提交次数 / 分值 / 我的最高分） |
| 班级 | 班级信息（课程、班级、分数、作业次数） |

## 4. 数据来源与刷新策略

| 事项 | 策略 |
| --- | --- |
| 启动时 | 读本地 SQLite（已全量离线 358 题）→ 秒开，**不发任何请求** |
| 刷新 | 只在**手动点刷新**时联网；绝不轮询、不后台定时 |
| 提交后 | 只拉取结果**一次**；✱ 若站点还没评完，最多再补拉 1–2 次（间隔几秒），不做持续轮询 |
| 节流 | 沿用加载器那套：串行 + 请求间隔下限 |

## 5. 我的假设（请重点核对，✱ 都是推断）

1. ✱ **去掉「考试列表」**。站点"我的班级"里还有考试列表，按"去掉一些功能、专注代码编写/提交/数据查看"，我倾向不做。
2. ✱ **提交走"方式 1 源码内容直接提交"**（POST `sourcecode`），不用文件上传。代码本来就在编辑器里，绕道写临时文件再 multipart 上传没好处。
3. ✱ **完型填空的题面残缺代码可一键导入编辑区**。已验证：站点提交页的代码框永远是空的，不预填，所以骨架只能从题面来。
4. ✱ **编辑器能力范围**：语法高亮、行号、括号匹配、等宽字体。不做自动补全 / LSP / 调试（"代码简单编辑"）。
5. ✱ **主题**：浅色为主，深色可选，默认跟随系统。
6. ✱ **编辑器是唯一例外**：不手绘，用真实文本控件（见问题一）。
7. ✱ **班级/作业/题库的写操作入口全部不出现**：不提供选课、退课、删除提交、发表评论等。
8. ✱ **提交前做本地保护**：显示该题剩余提交次数（每题 100 次），代码为空时不允许提交。
